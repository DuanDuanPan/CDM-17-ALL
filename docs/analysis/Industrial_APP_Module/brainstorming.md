# 工业 APP 模块 - 头脑风暴与架构分析

## 1. 核心概念回顾
目标是构建一个**低代码工业平台**，允许专家将知识封装为可复用的工具（**组件**），通过配置实例化为**插件**，并编排成工作流（**APP**）。

**层级定义：**
- **组件 (Component - 原始能力):** 类似于“类 (Class)”。例如：一个 Excel 计算文件，一个 Python 脚本 `calc_stress.py`，或者 `NX.exe` 的执行路径。
- **插件 (Plugin - 实例化):** 类似于“对象 (Object)”。是组件的一个配置后的实例。
    - *示例:* “弹簧计算插件”是“Excel 组件”的一个实例，加载了 `spring.xlsx`，将输入 A 映射到单元格 B2，将输出映射自单元格 C5。
    - *特性:* 输入/输出映射 (I/O mapping)，UI 配置 (自定义表单)，逻辑挂钩 (前后处理脚本)。
- **APP (应用 - 工作流):** 类似于“系统 (System)”。是由 Rete.js 连接的插件组成的有向无环图 (DAG)。

## 2. 技术架构头脑风暴

### A. 画布 (Rete.js)
- **为什么选择 Rete.js?** 优秀的基于节点的流式编程库，适配 React/Vue。
- **定制需求:**
    - **自定义节点:** 需要专门的“工业插件”节点，显示状态（就绪、运行中、错误）、微型可视化（如进度条）和输入插槽。
    - **控制流 vs 数据流:** 连线仅代表数据传输，还是也代表执行顺序？
        - *提议:* 混合模式。使用数据输入来驱动依赖执行（类似 Make/n8n 机制）。
    - **子图 (Sub-graphs):** 一个 APP 应该可以作为“插件”嵌套在另一个 APP 中（分形结构）。

### B. “封装器”引擎（Web 架构特别版）
**架构决策：Web 应用模式**
由于浏览器沙箱限制，Web 前端无法直接通过路径调用客户电脑上的 `NX.exe` 或 `Excel.exe`。因此需要**混合架构**：

1.  **Web 前端 (React/Vue + Rete.js):**
    -   负责 UI、画布编排、逻辑配置。
    -   只展示轻量化结果（GLTF 模型、PDF 报告）。
2.  **本地/远程执行代理 (Execution Agent):**
    -   这是一个安装在用户电脑（或高性能计算服务器）上的**后台服务**（类似 Docker Daemon 或 Steam 客户端）。
    -   **功能:**
        -   Web 端发送指令：“运行 NX，参数 A=10”。
        -   Agent 在本地调用 `NX.exe`，生成结果文件。
        -   Agent 将结果文件（如轻量化后的 3D 模型）上传回 Web 端展示。
    -   **优势:** 用户可以使用本地购买的昂贵 CAD 许可证，无需云端通过昂贵的虚拟化方案。

### C. 组件驱动器 (Driver)
每个组件必须由一个标准的“驱动器”进行封装（运行在 Agent 中）：
1.  **代码驱动:** 运行 Python/Java/JS/DLL。
2.  **Excel 驱动:** 无需安装 Office，使用 Python `pandas` 或 Node `SheetJS` 直接读写 xlsx 文件。
3.  **CAD/CAE 驱动 (重型):** 调用本地安装的软件（NX/Creo/Ansys），通过脚本接口（Journal/API）执行一系列操作，最后输出轻量化格式。

### D. 数据流与参数传递
- **全局上下文 (Global Context):** 一个 APP 需要“开始”节点（全局输入）和“结束”节点（报告/结果）。
- **类型安全:** Rete.js 的插槽 (Socket) 应根据数据类型（数字、字符串、文件、几何体、数组）进行颜色编码。

### E. 可视化 (轻量化展示)
用户提到了 "Office, CAD, CAE"。
- **Office:** 虽然 Excel 用于计算，但展示可用 PDF 或 HTML 表格。
- **CAD (3D):** Agent 将 PRT/ASM 转换为 **GLTF/OBJ**，Web 端使用 `Three.js` 展示。
- **CAE (仿真结果):** Agent 生成 **VTK** 或云图截图，Web 端使用 `vtk.js` 展示。

## 3. 插件设计的 UI/UX “低代码”化
当专家配置插件时，他们需要为最终用户设计界面：
- **输入设计器 (Input Designer):** 专家可以为算法参数配置 UI 控件。
    -   **示例 - 弹簧长度:** 专家放置一个“滑块 (Slider)”控件，范围 0-100。
    -   **交互:** 最终用户在运行 APP 时，不是输入数字，而是**拖动滑块**。
- **实时预览 (Real-time Preview):**
    -   *概念:* 如果勾选“实时运行”，当用户**拖动滑块**改变参数时，系统立即在后台触发一次快速计算（如简单的 Python 公式），并在界面上实时刷新结果图表。对于重型 CAD，通常禁用此功能或使用“简化模型”进行预览。

## 4. 知识管理 (SECI 模型)
- **S (社会化):** 共享 APP 库。插件的评论、评分。
- **E (外化):** 将个人的私有 Excel 表格转化为具有标准化输入/输出的“插件”。
- **C (组合):** 连接多个插件创建新 APP。
- **I (内化):** 仪表盘分析：统计哪些组件被高频使用，哪些参数范围最常被测试，从而提炼设计规范。
