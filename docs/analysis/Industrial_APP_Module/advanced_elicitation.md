# 高级需求启发 (Advanced Elicitation)

本阶段旨在深入挖掘系统的**隐性需求**与**技术约束**，将“高层概念”转化为“工程规范”。

## 1. 核心对象: 组件 (Component) 的数据契约
如果组件是一切的基础，我们需要严格定义它是什么。
**核心问题:** 所谓“组件”，在数据库/文件系统中究竟长什么样？

### 场景模拟
假设我有一个 Python 脚本 `calculate_spring.py`，输入是 `length`, `diameter`，输出是 `k_factor`。
我们需要一个 JSON Schema 来描述它，以便 Rete.js 能自动生成节点。

**待确认细节:**
- **自描述性:** 组件是否包含 Metadata（作者、版本、工业分类）？
- **环境依赖:** 如果是 Python 组件，它是否需要指定 `requirements.txt`？如果是 CAD 组件，是否指定 NX 版本？
- **I/O 类型系统:** 我们需要定义一套标准类型。
    - `Primitive`: String, Number, Boolean
    - `Industrial`: `FileRef` (文件路径), `Geometry` (GLTF流), `Table` (数据集)

**决策点 1:** 组件的定义文件是否应该包含 UI 布局信息？还是 UI 布局完全由“插件”阶段定义？
*   *建议:* 组件只定义 I/O 接口 (Interface)，插件定义具体的 UI 呈现 (Implementation)。

## 2. 执行模型: 谁来指挥奏乐？
当用户点击 Rete 画布上的“运行”按钮时，发生了什么？

### 模式 A: 编排在云端 (Server-Side Orchestration)
1. 浏览器将 JSON 图发送给 Web 服务器。
2. Web 服务器解析图，发现需要调用本地代理。
3. Web 服务器通过 WebSocket 指挥用户的本地代理。
*   *优点:* 状态可持久化，容易实现“断点续传”。
*   *缺点:* 延迟高，架构复杂。

### 模式 B: 编排在浏览器 (Client-Side Orchestration)
1. Rete.js 引擎在浏览器中遍历节点。
2. 当遇到“本地组件”节点时，浏览器直接通过 `localhost:port` (WebSocket) 发送指令给本地代理。
3. 本地代理执行完返回结果，浏览器继续遍历下一个节点。
*   *优点:* 响应极快（尤其是“拖动滑块”实时预览场景），架构简单。
*   *缺点:* 如果浏览器关闭，流程中断。
*   *倾向:* 鉴于“实时性”和“设计工具”的定位，**模式 B 可能更合适**。

## 3. 插件的“实例化”深度
插件是组件的实例。
**核心问题:** 插件是否允许“篡改”组件的逻辑？

- **场景:** 专家 A 发布了标准“螺栓校核”组件。专家 B 在 APP 中使用了它，但发现公式有一点小问题。
- **选择:**
    1. **严格模式:** 专家 B 必须继承/复制组件，修改代码，保存为新组件，再使用。
    2. **灵活模式:** 专家 B 可以在插件实例中“注入”一段 Patch 代码，仅对当前 APP 生效。
*   *权衡:* 灵活模式利于快速迭代，但不利于知识标准化 (SECI)。

## 4. 本地代理 (Local Agent) 的安全性
这是企业级应用最大的风险点。Web 页面可以直接指挥本地电脑运行 EXE 或 Python 脚本。

**风险:** 恶意网页可能通过本地代理删除用户文件。
**对策:**
- **白名单机制:** 代理只允许运行特定目录下的脚本/程序？
- **沙箱化:** 所有 Python 脚本必须在 Docker 或 venv 中运行？
- **签名校验:** 只有经过平台“审核签名”的组件才能被代理执行？

## 5. 工业数据流转 (Files vs Data)
在 Rete 连线中，我们传递的是什么？
- **小数据 (参数):** 直接通过 JSON 传递数值。
- **大数据 (CAD 模型/仿真结果):**
    - 方案 1: **传递路径 (Path Passing)**。例如 `C:\Temp\output.prt`。
        - *限制:* 要求所有插件都在同一台机器上运行。
    - 方案 2: **文件对象存储 (File Object Store)**。上一个节点执行完，将文件上传到 MinIO/S3，下游节点下载。
        - *优势:* 支持分布式（云端节点 + 本地节点混合）。
        - *劣势:* 所有的中间结果都要上传下载，速度慢。
    - *混合方案:* 默认传路径（本地闭环），如果跨越了边界（本地->云端），则自动触发上传。

## 6. 调试与日志 (Debugging)
专家如何调试 APP？
- **断点 (Breakpoint):** 能否在某个节点暂停，查看当前的 Excel 临时文件？
- **重放 (Replay):** 修改了某个参数，能否只从修改点开始重新运行下游节点？（Rete 默认不支持，需要自定义缓存层）。

---

请针对以上 6 点（特别是 **执行模型** 和 **数据流转**）进行思考。您的选择将直接决定架构的复杂度。
